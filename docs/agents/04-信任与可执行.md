# 04 · 信任与可执行

相似度 ≠ 可执行。星枢必须把 **裁决元数据** 和正文一起返回。

## 1. trust（建议枚举）

| 值 | 含义 | Agent 态度 |
|----|------|------------|
| `canon` | 来自章程/锁/白名单权威源 | 高信任；仍建议 readback |
| `source` | 有明确来源、人工或高质写入 | 可执行候选 |
| `synthesis` | 模型蒸馏/综合 | 当线索，需验证 |
| `hearsay` | 弱来源或传闻 | 仅提示 |
| `superseded` | 已被废止 | 丢弃现行 |

实现可增减，但必须有 **「不可当现行」** 与 **「权威」** 两端。

## 2. executable

布尔或三态：

- `true`：在未 supersede、未过期前可作方案  
- `false`：历史/草稿/已废止/缺前置条件  

**规则**：`executable=false` 禁止直接改生产/写关键配置。

## 3. readback

当条目对应 L1 权威文件时：

```json
{
  "readback": {
    "kind": "note|lock|config",
    "uri": "logical://vault/gateway-lock",
    "hint": "改网关前必读"
  }
}
```

- `uri` 用**逻辑标识**或相对文档 id，勿写死某台机器绝对路径（本设计文档层）  
- 实现层可映射到真实路径，但 **契约层保持可移植**  
- Agent：**有 readback 必回读**，禁止只信 chunk 摘要改关键系统  

## 4. composed 结果

ask 可提供 `composed`：

```json
{
  "composed": {
    "executable": true,
    "trust": "source",
    "summary": "一句话现行建议",
    "caveats": ["需先验证端口占用"]
  }
}
```

合成失败时：`executable=false`，附原因，而不是硬编答案。

## 5. 与 Reranker 的关系

Reranker 只调整排序，**不能单独把 hearsay 抬成 canon**。  
信任来自来源与生命周期，不来自 cross-encoder 分数。
